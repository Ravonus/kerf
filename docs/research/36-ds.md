## 2. Decisions

- **Primitives live in `@weft/warp`, not `weft/ds`.** weft can't depend on ui-core (nothing above weft gets installed), and one import is simpler for an agent.
- **`weft/ds` is names and types.** It has no runtime, so it costs nothing.
- **`Switch` from §6 is `Row reflow`, and `Surface` is `Card`.** `Switch` is warp's toggle and `<Surface>` is weft's canvas.
- **`Text` shares a name with `weft/text`'s.** Accepted: they're different imports, and warp's is the one for page copy.
- **A raw colour never gets an autofix.** Which token it should be is a design decision. A spacing value exactly on a scale step gets a safe fix.
- **Token codes (D001–D007) need `@weft/warp` in package.json.** A raw Tailwind or own-CSS app is left alone. Headless `@weft/ui-core` doesn't count: it ships no tokens, so a fix would point at variables that don't exist. The a11y codes run in every app.
- **`// weft-allow D001: <reason>` needs a reason.** `check: { design: false }` turns the family off, so the strong default stays one setting from anything else.
- **warp's D010 stays contrast.** The spec's D010 for missing names became D030 and D031. D040 and D081 stay reserved.

Not built: a Keel recipe as a seed (the repo has no format for it), a `tokens(el)` reader, section, page and type tokens in DTCG, a `--render` mode, and the Zod seed rework.

## 3. The exit check

`evals/ds-exit.mjs` gives one brief (three screens: settings, customers, pricing) to fresh `claude -p` sessions: 6 stacks × Haiku and Sonnet × 3 samples, 36 sessions, $7.13. Each app is audited from outside in Chromium the same way, so no stack gets its own rules: axe in light and dark at 1280 and 390 plus the invalid form and open dialog, focus, overflow, distinct computed values, role drift and 11 brief checks.

The bar, set before any run:

- a11y: weft/ds axe nodes below raw Tailwind's.
- Consistency: distinct values below raw Tailwind's, and role drift no higher.
- Brief: weft/ds at least raw Tailwind's.

| Means over 6 sessions | weft/ds | raw Tailwind | Bar |
|---|---|---|---|
| axe nodes | 0 | 5.3 | met |
| distinct computed values | 79 | 62 | **missed** |
| role drift | 17 | 13 | **missed** |
| brief | 10.8/11 | 10.8/11 | met |

Beyond the bar, weft/ds had no overflow (Tailwind 1.0), followed dark mode on every screen (Tailwind 2.5/3, one session never did) and had 0.3 raw values per 100 lines (0.9). The other stacks were worse on a11y: Solid 8, Radix 9, Zustand 12 and MUI 46 axe nodes. The 26 focus-lost mean for MUI is the largest single problem in the table.

### Why consistency missed

The extra values come mostly from the design system, not from agents drifting. Mean distinct values by property:

| Property | weft/ds | raw Tailwind |
|---|---|---|
| line-height | 13.2 | 7.5 |
| background | 13.5 | 7.7 |
| spacing | 19 | 13.2 |
| border colour | 5.2 | 2.4 |
| font family | 3 | 1 |
| text colour | 7.3 | 11.7 |
| font size | 7 | 7.8 |
| font weight | 3 | 4 |

Fluid type gives each size its own computed line-height, tone channels add backgrounds and borders, and warp's spec has three families. Agents using it got fewer text colours, sizes and weights than the Tailwind agents did. The metric counts values, not whether they came from a scale, so it can't tell a token from a stray hex. That's a reason to read the miss carefully, not a reason to call it met: the bar was set first, so it stands. Lowering warp's values would be a redesign, which isn't Phase 4's to make, and moving the bar after seeing the result would make it meaningless.

Role drift is a real miss. One Sonnet app has `h1` at both 30 and 52 px and `h2` at both 20 and 30 px, because `Heading` lets `role` differ from `level` and nothing says which role a page title takes. That app also left its nav links at the browser's default blue: it wrote a bare `<a>` in its own `<nav>` instead of using `Shell`, and warp has no standalone link primitive or base style for `a`. No D-code catches this. These are the two most useful things to fix next (§5).

### Things to disclose

- "Agreement between sessions" (48% vs 9%) was added after the pilot and is reported only. It isn't part of the bar. It favours weft/ds, so it shouldn't be used to offset the miss.
- n=6 per stack, three per model. Means hide spread: raw Tailwind ranges from 0 to 12 axe nodes.
- Size is a real cost. weft/ds apps average 41.7 KB br against 12.1 for raw Tailwind. That is under the 50 KB ceiling and over the 10 KB goal.
- The eval's kept apps in `evals/compare/design` are the `sonnet.1` sessions, so the chart shows one app per stack, not the means.
- The audit reads computed styles, so it doesn't judge how a design looks.
